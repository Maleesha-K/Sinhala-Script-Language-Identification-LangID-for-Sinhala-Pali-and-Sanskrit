\title{A Benchmark for Sinhala-Script Language Identification: \\ Disambiguating Sinhala, Pali, and Sanskrit in Closed and Open World Contexts}

\author{Anonymous ACL submission}

\begin{document}
\maketitle

\begin{abstract}
Language identification systems generally assume that when a writing system belongs primarily to a single nation, the script itself indicates the language. For the Sinhala script, this assumption fails. For more than two millennia, the script has also served as the primary written medium for canonical Pali and classical Sanskrit. Because standard language identification tools map all Sinhala characters directly to modern Sinhala, they overlook Pali and Sanskrit entirely. In this paper, we examine this script-sharing challenge across both isolated and multilingual settings. We find that while complete sentences are easily classified by standard models, shortening inputs to single words causes deep neural networks to stumble, whereas simple subword and character-level models remain dependable. We also show that while fine-tuning foundation models erases their knowledge of global languages, a two-stage routing pipeline resolves script ambiguity without any loss to pre-existing capabilities.
\end{abstract}

\section{Introduction}
Language Identification (LangID) is a standard workhorse in modern NLP pipelines, quietly filtering web crawls, routing machine translation requests, and sorting text archives \cite{jauhiainen2019automatic,lui-baldwin-2012-langid}. For widely used writing systems like Latin or Cyrillic, models are naturally trained to distinguish among dozens of languages sharing the same letters. But when a writing system is strongly associated with a single modern national language, models often make a coarse assumption: they treat the script itself as an orthographic monolith.

That assumption breaks down completely for the Sinhala script (Unicode block \texttt{U+0D80}--\texttt{U+0DFF}). In Sri Lanka and Theravada Buddhist scholarship, the Sinhala script has not been used solely for \textbf{Sinhala} (an Indo-Aryan language spoken by over 17 million people). For more than two millennia, it has also been the primary written medium for \textbf{Pali} (the liturgical language of Theravada Buddhism) and \textbf{Sanskrit} (the classical scholarly language of South Asian philosophy, grammar, and medicine). In fact, the Theravada Buddhist canon (\textit{Tipitaka}) was first committed to writing in the Sinhala script in the first century BCE at the Aluvihara rock temple in Matale, Sri Lanka \cite{Walshe_1983}. Over the centuries, hundreds of thousands of palm-leaf manuscripts and modern printed editions have preserved Pali and Sanskrit entirely in Sinhala letters.

Because planetary-scale LangID tools---like fastText LID-176 \cite{joulin-etal-2017-bag}, GlotLID v3 \cite{kargaran-etal-2023-glotlid}, NLLB LID-218 \cite{costa2022no}, and OpenLID-v2 \cite{burchell-etal-2023-open}---map every Sinhala character directly to modern Sinhala (\texttt{sin} or \texttt{sin\_Sinh}), they have exactly zero recall on Sinhala-script Pali and Sanskrit. They lump all three languages into a single label, quietly corrupting multilingual corpora and web crawls.

In this paper, we examine this script-sharing challenge by addressing two central research questions:
\begin{enumerate}
    \item \textbf{When context is stripped down to isolated words, what architectural inductive biases allow models to distinguish closely related languages written in the same script?}
    \item \textbf{In an open-world setting with global background languages, how can foundation models be adapted to resolve local script confusion without destroying their pre-trained global knowledge?}
\end{enumerate}

To answer the first question, we assemble a curated, document-isolated target corpus of 74,318 sentences covering Sinhala, Pali, and Sanskrit in the Sinhala script. We then evaluate seven from-scratch baseline architectures under severe context deprivation, showing why character $n$-grams and subwords beat deep neural networks when inputs are cut down to single words.

To answer the second question, we evaluate foundation models on three 11-language hybrid benchmarks constructed from FLORES+, CommonLID, and WiLI-2018. We show that while naive fine-tuning induces severe catastrophic forgetting on global languages, a simple two-stage routing pipeline fixes script ambiguity with 0.0\% degradation on background languages.

\section{Dataset Construction and Taxonomy}
\label{sec:dataset}

\subsection{Curated Target Corpus}
Distinguishing languages within the same script requires clean, balanced data. We assembled a 74,318-sentence target corpus from historical, canonical, and digital sources (summarized in Table \ref{tab:target_corpus}; full provenance in Appendix \ref{sec:appendix_data_provenance}):
\begin{itemize}
    \item \textbf{Sinhala (\texttt{Sinh-Sinh}, 32,263 sentences):} Sourced from the SiPaKosa repository (historical and Buddhist biographical writing) and the Sinhala side of a sentence-aligned Pali--Sinhala parallel translation corpus.
    \item \textbf{Pali (\texttt{Pali-Sinh}, 29,317 sentences):} Drawn from the Pali side of the canonical translation corpus and the SiDiaC-v2.0 corpus \cite{jayatilleke-de-silva-2025-sidiac}, containing Theravada \textit{Tipitaka} texts, commentaries (\textit{Atthakatha}), and grammatical treatises \cite{Walshe_1983}.
    \item \textbf{Sanskrit (\texttt{San-Sinh}, 12,738 sentences):} Digitized Sanskrit in Sinhala script is genuinely hard to find. We combined three sources: \textbf{SansinNT} (7,953 sentences from a historical 19th-century Sanskrit New Testament printed in Sinhala script); classical poetry from the \textbf{Digital Corpus of Sanskrit} (DCS; 4,684 sentences) \cite{hellwig2010dcs}, transliterated from SLP1 Romanization into Sinhala script using the verified phonetic mappings of \textit{Aksharamukha} \cite{rajan2023aksharamukha}; and a devotional \textit{kavaca} text (101 sentences) from SiDiaC-v2.0 \cite{jayatilleke-de-silva-2025-sidiac}.
\end{itemize}

A common pitfall in LangID benchmarking is randomly shuffling sentences across splits. When sentences from the same book appear in both train and test sets, models easily score high simply by memorizing topical vocabulary. To prevent this, we enforced a strict \textbf{group-stratified split}: sentences from any given literary work or chapter were kept together as an atomic block and placed entirely into training (81.1\%), validation (9.4\%), or testing (9.5\%).

\subsection{11-Language BCP-47 Hybrid Taxonomy}
In real applications, Sinhala-script text does not exist in a vacuum; it appears alongside regional and global languages. To test models in realistic conditions without leaking evaluation data, our taxonomy adopts the \textbf{BCP-47 standard} \cite{phillips2009tags} (\texttt{[Language]-[Script]}):
\begin{itemize}
    \item \textbf{Target Classes:} \texttt{Sinh-Sinh}, \texttt{Pali-Sinh}, \texttt{San-Sinh}.
    \item \textbf{Global Background Classes:} \texttt{San-Deva} (Devanagari Sanskrit), \texttt{Eng-Latn} (English), \texttt{Tam-Taml} (Tamil), \texttt{Hin-Deva} (Hindi), \texttt{Ben-Beng} (Bengali), \texttt{Ara-Arab} (Arabic), \texttt{Fre-Latn} (French), and \texttt{Ger-Latn} (German).
\end{itemize}

We built three hybrid evaluation benchmarks by taking the official test partitions of FLORES+ \cite{goyal-etal-2022-flores}, CommonLID \cite{suarez-etal-2026-commonlid}, and WiLI-2018 \cite{thoma2018wili}, replacing their monolithic Sinhala rows with our 7,047 held-out target sentences, and keeping Devanagari Sanskrit alongside background languages.

To train from-scratch baselines on this open-world task under clean conditions, we also constructed a balanced multi-language corpus of \textbf{110,000 sentences} (10,000 sentences per class across all 11 languages; 9,000 train / 1,000 val). Target sentences were drawn strictly from our target training split, ensuring zero overlap with the test set.

\section{Analysis and Findings}
\label{sec:experiments}

\subsection{Closed-World Baselines \& The Fragment Test}
We trained seven representative architectures strictly from scratch on our target training set:
\begin{enumerate}
    \item \textbf{Multinomial Naive Bayes (MNB):} Character $n$-grams ($n \in [1, 5]$) with sublinear TF-IDF scaling \cite{mccallum1998comparison}.
    \item \textbf{Linear SVM:} One-vs-Rest formulation with $C=1.0$ over character $n$-grams \cite{joachims1998text}.
    \item \textbf{Logistic Regression (LogReg):} L2-regularized multinomial loss.
    \item \textbf{XGBoost:} Gradient-boosted trees (100 estimators, max depth 6) \cite{chen2016xgboost}.
    \item \textbf{Char-CNN:} Three parallel 1D convolution banks (kernel sizes 3, 5, 7; 128 filters each) with global max-pooling \cite{zhang2015character}.
    \item \textbf{Char-BiGRU:} Bidirectional GRU (128 units per direction) over 64-dimensional character embeddings.
    \item \textbf{fastText (From Scratch):} Two-layer shallow network with 100-dimensional embeddings and subwords ($n \in [3, 6]$) \cite{joulin-etal-2017-bag}.
\end{enumerate}

\paragraph{Full Sentences are Deceptively Easy.}
As Table \ref{tab:stress_testing} shows, when models have access to full-length sentences, every single architecture performs well. All seven models score above 0.984 Macro-F1, with Linear SVM leading at 0.9960. If one evaluates only on complete sentences, it appears that any standard classifier has solved the problem.

Real-world text, however, is rarely that neat. Search queries, dictionary headwords, and OCR output from damaged palm leaves often consist of single words or brief phrases. To see what happens under extreme contextual deprivation, we generated synthetic fragments by taking the first 5, 3, and 1 words of each test sentence.

As input length drops, performance splits wide open. On single words, the deep neural networks and margin classifiers fall apart: Linear SVM drops from 0.9960 down to 0.6099 (a drop of nearly 40 points), while Char-BiGRU sinks from 0.9948 to 0.6916.

Meanwhile, Multinomial Naive Bayes holds up with a Macro-F1 of \textbf{0.8584}, and fastText stays strong at \textbf{0.8027}.

\paragraph{Why Subwords and $N$-Grams Win on Short Text.}
This difference comes down to the inductive bias of each architecture. Recurrent networks and margin classifiers look for broader sentence structure and sequence flow. When reduced to an isolated word, they starve for context.

Sinhala, Pali, and Sanskrit, however, are highly inflected languages. Even in an isolated word, morphological clues are everywhere:
\begin{itemize}
    \item \textbf{Pali} relies on distinctive nominal case endings (like the genitive singular in \textit{-assa} or instrumental plural in \textit{-\={e}hi}) and verbal endings (\textit{-ti}, \textit{-ntu}).
    \item \textbf{Sanskrit} features characteristic consonant clusters and case inflections (like \textit{-\={a}t}, \textit{-bhy\={a}m}, and visarga forms).
    \item \textbf{Sinhala} uses modern colloquial postpositions and verbal markers (like \textit{-v\={e}}, \textit{-\={e}ya}, \textit{-da}).
\end{itemize}
Because MNB calculates likelihoods over all overlapping character $n$-grams, it catches these diagnostic inflectional fragments directly. fastText does something similar through its subword bag-of-characters \cite{joulin-etal-2017-bag}. For short-text and OCR applications where sentence syntax is missing, simple subword and $n$-gram models are far more dependable than heavier neural architectures.

\paragraph{Zero-Shot Collapse.}
As Table \ref{tab:open_world} shows, all off-the-shelf foundation models hover around 0.68--0.71 Macro-F1 across FLORES+, CommonLID, and WiLI-2018. The reason is straightforward: because every stock model assigns Sinhala script strictly to modern Sinhala, their recall on Sinhala-script Pali and Sanskrit is exactly 0.0\%.

\paragraph{The Failure of Naive Fine-Tuning.}
A common knee-jerk reaction to classification errors is to take a pre-trained model and fine-tune it on target data. But when one fine-tunes fastText LID-176 or OpenLID-v2 exclusively on our three target languages, catastrophic forgetting kicks in immediately \cite{mccloskey1989catastrophic,french1999catastrophic}. The model learns the three target classes, but its representations for other languages degrade rapidly; it begins predicting English, French, and Tamil as Sinhala or Pali. Across the 11-language benchmarks, Macro-F1 collapses to $\approx 0.26$.

\paragraph{Why Two-Stage Routing Just Works.}
Instead of fighting catastrophic forgetting with complex regularization or replay buffers, one can sidestep it entirely with a simple two-stage routing setup:
\begin{itemize}
    \item \textbf{Stage 1 (General Router):} The frozen stock foundation model classifies the input text. If it predicts any non-Sinhala language (English, Tamil, Devanagari Sanskrit, etc.), that prediction is returned directly.
    \item \textbf{Stage 2 (Specialist):} If and only if Stage 1 predicts Sinhala script (\texttt{si} or \texttt{sin\_Sinh}), the text is handed over to our fine-tuned specialist classifier to make the 3-way call between Sinhala, Pali, and Sanskrit.
\end{itemize}
Because the Stage 1 model is never modified, there is \textbf{zero catastrophic forgetting} on background languages. At the same time, Stage 2 resolves the localized script confusion.

As Table \ref{tab:open_world} shows, Two-Stage Routing lifts every foundation model to 0.95--0.97 Macro-F1, beating both the zero-shot foundation models and the from-scratch multi-language baselines. ConLID 2-Stage achieves the highest overall scores (0.9752 on FLORES+, 0.9561 on CommonLID, 0.9738 on WiLI-2018).

\subsection{The Dialect Continuum Headache}
A final practical lesson comes from models with hundreds of fine-grained regional dialect heads, like OpenLID-v2. When evaluated on Devanagari Sanskrit in CommonLID, OpenLID-v2 scores an F1 of just 0.0276 (detailed in Appendix Table \ref{tab:common_full}). Rather than predicting Sanskrit, it scatters predictions across closely related North Indian regional dialects (Awadhi, Bhojpuri, Maithili, and Hindi).

While adding fine-grained dialect labels is helpful for living spoken varieties, it creates serious confusion for classical languages that share ancient roots and vocabulary with those dialects. Models with cleaner, standardized language taxonomies (like GlotLID v3 and ConLID) are much more robust against this kind of fragmentation.

\section{Conclusion}
Treating the Sinhala script as a language label erases two thousand years of canonical Pali and classical Sanskrit literature from digital NLP pipelines. In this work, we built the first dedicated benchmark to study this problem. Under severe context deprivation (down to single words), character $n$-gram models and subword embeddings prove much more reliable than deep sequence models by picking up on inflectional affixes. In open-world settings, naive fine-tuning wipes out global language knowledge, but a modular two-stage routing pipeline eliminates script ambiguity while keeping pre-trained capabilities completely intact.

Our datasets, benchmark splits, and models are available at: \url{https://github.com/anonymous-submission/sinhala-script-langid}.

\section*{Limitations}
We note three main limitations:
First, because natively digitized Sanskrit in Sinhala script is scarce, about 37\% of our Sanskrit target data (4,684 sentences from the Digital Corpus of Sanskrit) was transliterated from SLP1 Romanization using \textit{Aksharamukha}. While phonetically sound, digital transliteration does not capture all the historical scribal ligatures found in physical manuscripts.
Second, our benchmark tests clean digital text. Severely degraded palm-leaf manuscripts with OCR noise, broken characters, and non-standard orthography require dedicated image preprocessing before LangID can be applied.
Finally, while our 11-language hybrid benchmarks provide balanced testing across major language families, they do not cover all 200+ world languages simultaneously.

\section{Baseline Model Architectures and Hyperparameters}
\label{sec:appendix_architectures}

All seven from-scratch baseline models were trained using the following standardized configurations:
\begin{itemize}
    \item \textbf{Multinomial Naive Bayes:} Scikit-learn implementation \cite{pedregosa2011scikit}; character $n$-gram range $[1, 5]$; sublinear term frequency scaling; Laplace smoothing parameter $\alpha = 0.1$.
    \item \textbf{Linear SVM:} Scikit-learn \texttt{LinearSVC}; character $n$-grams $[1, 5]$; sublinear TF-IDF; squared hinge loss; regularization parameter $C=1.0$; tolerance $10^{-4}$; maximum iterations 2,000.
    \item \textbf{Logistic Regression:} Scikit-learn \texttt{LogisticRegression}; character $n$-grams $[1, 5]$; multinomial cross-entropy loss; L-BFGS solver; $C=1.0$; maximum iterations 1,000.
    \item \textbf{XGBoost:} \texttt{XGBClassifier} \cite{chen2016xgboost}; 100 estimators; learning rate $\eta = 0.1$; maximum tree depth 6; subsample ratio 0.8; colsample\_bytree 0.8; multi:softprob objective.
    \item \textbf{Char-CNN:} PyTorch implementation \cite{zhang2015character}; character vocabulary size 200; character embedding dimension 64; 3 parallel 1D convolution banks with kernel sizes 3, 5, and 7 (128 filters each); ReLU activation; global max-pooling; dropout $p=0.3$; AdamW optimizer (learning rate $10^{-3}$, weight decay $10^{-4}$); batch size 64; trained for 10 epochs with early stopping.
    \item \textbf{Char-BiGRU:} PyTorch implementation; character embedding dimension 64; 1-layer bidirectional GRU with 128 hidden units per direction; dropout $p=0.3$; linear classification head ($256 \to 3$); AdamW optimizer (learning rate $10^{-3}$); batch size 64; trained for 10 epochs with early stopping.
    \item \textbf{fastText (From Scratch):} Official C++ binary / Python API \cite{joulin-etal-2017-bag}; character subword $n$-gram range $[3, 6]$; embedding dimension 100; learning rate $\alpha = 0.5$; 10 epochs; hierarchical softmax loss; bucket size 2,000,000.
\end{itemize}
