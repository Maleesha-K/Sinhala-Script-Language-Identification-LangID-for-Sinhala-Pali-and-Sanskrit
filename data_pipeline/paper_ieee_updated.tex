\begin{abstract}
Most existing language identification (LangID) systems automatically assume that text written in the Sinhala script belongs exclusively to the Sinhala language. However, the Sinhala script is extensively utilized to transcribe Pali and Sanskrit, particularly in historical documents, religious scriptures, and scholarly publications. This assumption leads to systematic misclassification, thereby degrading the performance of downstream Natural Language Processing (NLP) tasks such as optical character recognition (OCR), machine translation, and historical text analysis. In this study, we propose the first dedicated LangID benchmark designed to differentiate Sinhala, Pali, and Sanskrit texts written entirely within the Sinhala script. Our investigation is structured across two major research phases. In Phase 1, we evaluate baseline machine learning models, character-level neural networks (Char-CNN, Char-BiGRU), and multilingual transformers under full-sentence and fragment stress-testing (1, 3, 5 words). In Phase 2, we expand our framework to benchmark 6 state-of-the-art model families (XLM-R Base, ConLID, fastText LID-176, GlotLID v3, NLLB LID-218, OpenLID-v2) evaluated zero-shot and fine-tuned across three hybrid benchmark datasets (FLORES+, CommonLID, WiLI-2018) across 11 target and global background languages. Our empirical results demonstrate that traditional probabilistic models excel on short sub-word text fragments, while fine-tuned specialist models eliminate script ambiguity and achieve over 0.97 Macro-F1 across target and global background languages.
\end{abstract}

\section{Introduction}
Language Identification (LangID) serves as a critical preprocessing component in multilingual Natural Language Processing (NLP) pipelines. While modern LangID models exhibit high accuracy for globally dominant languages, they often rely heavily on orthographic features, functioning under the assumption of a bijective mapping between script and language \cite{b1}, \cite{b4}. This assumption fails catastrophically when a single script is employed to write multiple distinct languages.

In Sri Lanka, the Sinhala script is the standard orthography not only for Sinhala but also for Pali and Sanskrit texts. Because existing tools associate the Sinhala script exclusively with the Sinhala language, they systematically fail to identify Pali and Sanskrit. This deficiency poses a significant barrier for downstream digital humanities research and NLP applications dealing with historical and liturgical documents.

To address this gap, this project introduces four primary contributions across two investigation phases:
\begin{enumerate}
    \item A comprehensive Sinhala-Script LangID Benchmark Dataset encompassing Sinhala, Pali, and Sanskrit (all written entirely within the Sinhala script).
    \item \textbf{Phase 1 Baseline \& Fragment Analysis:} A rigorous comparison of traditional ML (MNB, SVM), character-level neural networks (Char-CNN, Char-BiGRU), and transformers subjected to 1-, 3-, and 5-word fragment stress testing.
    \item \textbf{Phase 2 State-of-the-Art Evaluation:} Construction of three hybrid benchmark datasets (FLORES+, CommonLID, WiLI-2018) combining global background languages with target test data across 11 distinct language classes.
    \item \textbf{Phase 2 Fine-Tuned Evaluation \& Catastrophic Forgetting Mitigation:} Benchmarking 6 state-of-the-art model families and engineering mitigation strategies (such as Two-Stage Specialist Routing, LoRA Parameter-Efficient Adaptation \cite{b16}, C++ Causal Weight Preservation, and Head Expansion) to prevent background language degradation.
\end{enumerate}

\section{Dataset Construction}
To train and evaluate the proposed models, a unified, sentence-level dataset was compiled. Combining multiple sources was necessary to mitigate source-specific lexical biases:
\begin{itemize}
    \item \textbf{SiPaKosa \& SiDiaC-v.2.0:} These publicly available corpora provided a robust foundation for the Sinhala and Pali classes.
    \item \textbf{Historical \& Religious Publications:} Supplementary texts were curated from open digital libraries and religious commentaries.
    \item \textbf{Transliterated Sanskrit Data:} Due to a severe scarcity of native Sanskrit data natively digitized in the Sinhala script, the \textit{Aksharamukha} Asian Script Converter \cite{b3} was utilized to algorithmically transliterate classical Sanskrit texts from SLP1 Romanization into the Sinhala script, effectively resolving the data deficit.
\end{itemize}
To ensure methodological rigor, a strict group-stratified dataset split was enforced. Sentences originating from the same document, chapter, or text source were grouped together during splitting to guarantee zero data leakage across partitions. The complete target dataset comprises \textbf{67,332 sentences} across Sinhala, Pali, and Sanskrit in the Sinhala script, partitioned into:
\begin{enumerate}
    \item \textbf{Training Set (54,256 rows / 80.6\%):} Used for training supervised classifiers, character n-gram feature extractors, and fine-tuning neural network parameters.
    \item \textbf{Validation Set (6,029 rows / 9.0\%):} Reserved for validation loss monitoring, hyperparameter optimization, and early stopping criteria.
    \item \textbf{Held-Out Test Set (7,047 rows / 10.4\%):} Strictly isolated from all training steps and used exclusively for final Phase 1 fragment stress testing and Phase 2 hybrid benchmark evaluations.
\end{enumerate}

\subsection{Phase 2 Hybrid Benchmarking Datasets \& Tagging Taxonomy}
Evaluating models solely on target languages creates an artificial environment. In practical deployments, a classifier must distinguish target Sinhala-script languages from global background text (e.g., English, Tamil, German, Devanagari Sanskrit). In standard multilingual evaluation benchmarks (FLORES+, CommonLID, WiLI-2018), text written in the Sinhala script is universally tagged under a single generic Sinhala label (\texttt{sin\_Sinh}, \texttt{sin}, or \texttt{si}), while Pali and Sanskrit in the Sinhala script are entirely absent.

To maintain international compatibility, our benchmarking taxonomy strictly adheres to the \textbf{BCP-47 language tag standard} \cite{b18}, formatting each class as \texttt{[Language]-[Script]} (using ISO 639-3 3-letter language codes and ISO 15924 4-letter script codes):
\begin{itemize}
    \item \textbf{Target Sinhala-Script Classes:} \texttt{Sinh-Sinh} (Sinhala in Sinhala script), \texttt{Pali-Sinh} (Pali in Sinhala script), and \texttt{San-Sinh} (Sanskrit in Sinhala script).
    \item \textbf{Global Background Classes:} \texttt{San-Deva} (Sanskrit in Devanagari script), \texttt{Eng-Latn} (English in Latin script), \texttt{Tam-Taml} (Tamil in Tamil script), \texttt{Hin-Deva} (Hindi in Devanagari script), \texttt{Ben-Beng} (Bengali in Bengali script), \texttt{Ara-Arab} (Arabic in Arabic script), \texttt{Fre-Latn} (French in Latin script), and \texttt{Ger-Latn} (German in Latin script).
\end{itemize}

To construct our three hybrid benchmark datasets, we removed the original generic Sinhala-labeled rows (\texttt{sin\_Sinh} / \texttt{sin} / \texttt{si}) from the official benchmark corpora, while explicitly preserving Devanagari Sanskrit (\texttt{san\_Deva}) alongside global background languages. We then substituted them with our **7,047 expert-annotated target test rows** categorized into fine-grained ground-truth classes:
\begin{enumerate}
    \item \textbf{\texttt{flores\_plus.jsonl} (229,687 rows):} Removed original generic \texttt{sin\_Sinh} rows; inserted 1,012 \texttt{san\_Deva} records + 7,047 target test rows (\texttt{Sinh-Sinh}, \texttt{Pali-Sinh}, \texttt{San-Sinh}) + global FLORES+ background languages \cite{b15}.
    \item \textbf{\texttt{commonlid.jsonl} (380,277 rows):} Removed original generic \texttt{sin} rows; inserted 895 \texttt{san\_Deva} records + 7,047 target test rows (\texttt{Sinh-Sinh}, \texttt{Pali-Sinh}, \texttt{San-Sinh}) + CommonLID background languages \cite{b17}.
    \item \textbf{\texttt{wili-2018.jsonl} (241,047 rows):} Removed original generic \texttt{si} rows; inserted 1,000 \texttt{san\_Deva} records + 7,047 target test rows (\texttt{Sinh-Sinh}, \texttt{Pali-Sinh}, \texttt{San-Sinh}) + WiLI-2018 background languages \cite{b14}.
\end{enumerate}

To quantify the baseline necessity of this research, existing state-of-the-art models were evaluated in a zero-shot setting. Both fastText \cite{b1} and GlotLID \cite{b4} failed to identify Pali and Sanskrit, defaulting entirely to Sinhala or "other." This resulted in an aggregate Macro-F1 score of approximately 0.18, confirming that off-the-shelf solutions are inadequate for this task.

\subsection{Traditional Machine Learning Paradigms}
The core differentiator between Sinhala, Pali, and Sanskrit within the same script lies in their morphology—specifically prefixes, suffixes, and orthographic character combinations. Traditional models utilizing Character n-grams (ranging from 2 to 4 characters) combined with TF-IDF vectorization proved exceptionally adept at capturing these markers. Multinomial Naive Bayes \cite{b10} (Figure \ref{fig:cm_mnb}), in particular, excelled on short fragments because it treats n-gram frequencies probabilistically without relying on syntax. For example, the presence of the distinct Pali suffix ''\textit{-ssa}'' allows MNB to detect a high-probability marker immediately, rendering the surrounding sentence context unnecessary for accurate classification. Support Vector Machines \cite{b9} demonstrated similar robustness.

\subsection{Custom Deep Learning Architectures}
Character-level Neural Networks, including Convolutional Neural Networks (CNNs) \cite{b6} and Bidirectional Gated Recurrent Units (BiGRUs) \cite{b7}, were evaluated. By processing text character-by-character, these models autonomously learned the morphological boundaries of the languages, achieving perfect saturation (1.00 Macro-F1) on full sentences (see Figure \ref{fig:cm_cnn}). However, during the fragment test, their performance degraded slightly compared to rigid n-gram models. This is attributed to the models overfitting to the expected sequence lengths and padding distributions of full sentences, which are disrupted during aggressive fragmentation.

\subsection{Large Language Transformers}
Large multilingual transformers, such as XLM-RoBERTa \cite{b2} (Figure \ref{fig:cm_xlmr}), leverage immense pre-trained knowledge to understand complex syntactic structures. On full sentences, this contextual awareness allowed XLM-R to score flawlessly. However, transformers fundamentally rely on \textit{subword tokenization}. Rather than processing exact character markers, they partition words into tokens based on a vocabulary optimized for major global languages. When the input is restricted to fragments of 1-to-3 words, the transformer loses its primary heuristic: contextual syntax. Stripped of sentence structure, the subword embeddings fail to adequately discriminate between the highly inflected morphological roots of Pali and Sanskrit, causing the Macro-F1 score to drop significantly. For instance, on 1-word fragments, XLM-R's Macro-F1 dropped to 0.662, falling below even the baseline Logistic Regression model (0.680). Furthermore, models like mBERT \cite{b5} exhibited weaker performance overall, likely due to a comparatively lower representation of South Asian languages in their respective pre-training corpora.

\section{Phase 2: State-of-the-Art Evaluation \& Fine-Tuning Benchmarks}

Following Phase 1, Phase 2 expanded the benchmarking framework across six state-of-the-art model families: XLM-R Base \cite{b2}, ConLID, fastText LID-176 \cite{b1}, GlotLID v3 \cite{b4}, NLLB LID-218 \cite{b12}, and OpenLID-v2 \cite{b13}.

\subsection{Zero-Shot Baseline Failure on Hybrid Benchmarks}
Stock off-the-shelf SOTA models lack distinct classification heads for Pali and Sanskrit in Sinhala script. In zero-shot testing (Tables \ref{tab:flores_full}, \ref{tab:common_full}, \ref{tab:wili_full}), all Sinhala-script input text is predicted as Sinhala (\texttt{sin}/\texttt{sin\_Sinh}), resulting in zero-shot F1 scores of 0.00\% for Pali and Sanskrit.

\subsection{Mitigation of Catastrophic Forgetting via Targeted Adaptation Strategies}
Direct naive fine-tuning on a narrow domain dataset causes severe \textit{catastrophic forgetting}, wherein a classifier loses its decision boundaries for pre-trained global background languages. To preserve original language coverage while extending model capabilities to Sinhala-script Pali and Sanskrit, five complementary architectural and optimization strategies were engineered across model families:

\begin{enumerate}
    \item \textbf{Two-Stage Hierarchical Specialist Routing (OpenLID-v2 \& fastText LID-176):} Engineered specifically to resolve catastrophic forgetting in OpenLID-v2 (and fastText LID-176), a pre-trained Stage 1 global router intercepts input text. Non-Sinhala scripts (e.g., English, Tamil, Devanagari) are output directly. If Sinhala script (\texttt{si}/\texttt{sin\_Sinh}) is identified, text is routed to a Stage 2 specialist model fine-tuned for fine-grained 3-way disambiguation between Sinhala, Pali, and Sanskrit (all transcribed in the Sinhala script). This two-stage separation guarantees zero degradation on background languages.
    \item \textbf{Parameter-Efficient LoRA Adaptation with Mixed-Language Rebalancing (XLM-R Base):} To fine-tune the massive XLM-RoBERTa transformer efficiently, Low-Rank Adaptation (LoRA) \cite{b16} matrices were injected into the attention layers. This drastically reduced GPU memory and computational overhead during training. To prevent catastrophic forgetting, sample batches from global background languages were explicitly re-mixed into the training dataset during fine-tuning, preserving the model's pre-trained multilingual representations.
    \item \textbf{Weight-Preserving Classification-Head Extension \& C++ Continuation Training (NLLB LID-218):} A custom C++ patch (\texttt{extend-labels}) was compiled for fastText to grow the output matrix from 218 to 220 labels while copying pre-existing weight rows verbatim. True continuation training (\texttt{finetune-loaded}) fine-tunes in-memory weights with linear learning-rate decay ($lr=0.001$, 3 epochs), preventing embedding drift.
    \item \textbf{In-Place Head Extension with Xavier Initialization \& Early Stopping (ConLID):} The final PyTorch linear layer (\texttt{model.fc}) was expanded, preserving existing class weights while initializing new target class rows with Xavier uniform. Training combined AdamW ($lr=1e-4$), gradient accumulation ($eff.\ batch=32$), and validation F1 early stopping to prevent over-fitting.
    \item \textbf{Pretrained Vector Transfer \& Conservative LR Schedules (GlotLID v3):} Pretrained subword vectors from GlotLID (~2,100 languages) were exported to initialize training (\texttt{pretrainedVectors}), paired with a conservative schedule ($lr=0.005$, 5 epochs) to restrict weight drift.
\end{enumerate}

\section{Discussion \& Devanagari Script Dialect Analysis}
While target Sinhala-script languages achieved 0.96--0.98 F1 across all Phase 2 models, OpenLID-v2 exhibited a lower Macro-F1 (0.77--0.79) due to its handling of Devanagari Sanskrit (\texttt{san\_Deva}). In OpenLID-v2, stock Stage 1 splits Devanagari script text among fine-grained regional labels (Bhojpuri \texttt{bho\_Deva} 68.1\%, Maithili \texttt{mai\_Deva} 15.1\%, Kashmiri \texttt{kas\_Deva} 43.3\%), resulting in exact single-label match drop for \texttt{san\_Deva} (0.035 F1). In contrast, fastText LID-176 uses a unified \texttt{sa} label, maintaining 0.9594 to 0.9904 F1 for \texttt{san\_Deva}.

\FloatBarrier
\section{Conclusion}
This study highlights key insights across both research phases:
\begin{enumerate}
    \item \textbf{Phase 1:} Morphological sub-word models (Multinomial Naive Bayes, Char-CNN) outperform contextual transformers on short text fragments by capturing rigid character n-grams.
    \item \textbf{Phase 2:} Evaluating 6 state-of-the-art models demonstrates that fine-tuning and architectural adaptation (such as Two-Stage Specialist Routing for OpenLID-v2 and fastText, LoRA parameter-efficient adaptation with background data rebalancing for XLM-R, custom C++ weight extension for NLLB, and Xavier-initialized head extension for ConLID) eliminate script ambiguity while preserving high precision and recall across global background languages.
\end{enumerate}
